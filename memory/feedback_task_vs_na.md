## Правило маршрутизации

**1 действие = NA напрямую.** Не создавать Task-обёртку.  
**Task = минимум 2 NA.** Task — это проект с несколькими шагами.  
Если после декомпозиции в Task остаётся только 1 NA → Task лишний, схлопнуть в standalone NA и удалить Task.

**Why:** Task с 1 NA — бессмысленный overhead.

---

## Паттерны декомпозиции

**«X + Y» в названии задачи** → всегда 2 отдельных NA:
- «Бронь билета + проезд» → «Купить билет» + «Забронировать транспорт»

**Несколько однотипных объектов** → по NA на каждый:
- «Продать: шмотки, наполнитель, объектив» → 3 NA (по одному на каждый лот)

**Последовательная зависимость (research → action)** → NA на каждый шаг:
- «Разобраться с горшком для бонсая» → «Выбрать и купить горшок» + «Пересадить бонсай»
- «Чистка зубов» → «Выбрать клинику (цены, страховка)» + «Записаться» + «Прийти»

**Финансово-юридические/сложные** → исследование + реализация + передача:
- «Передача паролей» → «Составить список счетов» + «Изучить юридическое оформление» + «Передать»

**«Разобраться с...»** — слово-маркер: всегда есть research NA перед action NA.

**Купить + отправить** → «Купить X» + «Отправить X»

---

## Признаки правильного NA

- Название начинается с глагола конкретного действия: Купить, Записаться, Позвонить, Проверить, Отправить...
- Один человек, одно место, одно действие — без разветвлений
- Можно взять и просто сделать без предварительных решений (если решение нужно → это отдельный research NA)

---

## How to apply

При process-inbox и tasks-processing Part A:
1. Посчитать ожидаемые действия. Если 1 → NA напрямую. Если 2+ → Task + декомпозиция.
2. Для каждого NA: конкретный глагол, конкретный объект.
3. Если в Task после декомпозиции осталось ≤1 открытого NA → удалить Task, оставить NA standalone.
4. Учитывать «+» и «и» в названии как маркеры двух шагов.
5. Списки (A, B, C) → по NA на каждый элемент.
